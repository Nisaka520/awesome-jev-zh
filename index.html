The Real Ask
三个原语

所有 Jev 请求都是同一个形状：一份 state，加一组带类型的问题。问题只有三种。

Choice　从你给的选项里选一个。返回命中的 key、完整概率分布与置信度。单个问题最多 255 个候选。

Score　在你给的量表上打一个分。返回的是小数，落在档位之间，比档位本身更细。

Noul　这句陈述为真的概率，0 到 1。护栏、审核、语义检索都靠它。

同一次请求里的问题，对同一份 state 并行求值、彼此隔离。

问题之间互相看不见。这既是它快的原因，也画出了它的边界：需要串联推理的任务不适合它。

核心心法只有一句：问题尽量原子，组合逻辑写在你自己的代码里。

How to Use

怎么用对

03
置信度门控

答案告诉你「是什么」，置信度告诉你「要不要直接动手」。

绝大多数把 Jev 用砸的案例，都是拿着结果直接执行，不看 confidence。正确姿势是三段：高置信直接执行，中置信执行但打标，低置信上抛给 LLM 或人工。

阈值不能拍脑袋。跑一批你自己的真实数据，按置信度分桶统计准确率——模型宣称是校准的，0.7 那一桶长期就该在 70% 附近。这张表既是在定阈值，也是在验证它在你的数据上到底校不校准。

低置信度有两种成因，概率分布能分辨。

前两名咬得很紧　这条输入本身就跨两类，人来判也会犹豫。该上抛，或者承认你的分类体系有重叠。

分布接近均匀　模型没抓到信号。多半是 state 信息不够，或判据写得太模糊。

Limits

边界

05
它不能做什么

先把话说死，免得改造改过头。

  • 生成文本、代码、摘要——完全不会，这是设计。
  • 给出判断理由——只给概率，不给解释。
  • 多步推理——问题之间隔离，天生没有链。
  • 开放式抽取——得先出候选，再让它选。
  • 图像、音频、视频——当前只吃纯文本。
  • 保证判断正确——靠门控兜，不靠模型。

「不可能幻觉」要理解准确。

它指的是输出不可能违反 schema、不可能编出你没定义的选项——不是判断一定对。选错依然会发生。

还有两件事值得先知道：「快 193 倍」出自厂商自评，官方也标注了那是收益上限；中文场景至今没有任何公开评测，别把英文结论直接搬过来。
